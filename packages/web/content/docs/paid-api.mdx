Thuli screens one Ethereum wallet, free for people and paid for programs, under rulebook v2.

## The free check

`POST /api/check` takes `{"wallet": "0x..."}` and returns a decision. It needs no sign-in and no payment, never buys data, and costs only model credit, capped by the ceilings below. The site serves it, and its page, [/check](/check), calls it. A wallet's result sits at `/check/` followed by the lowercase address. `GET /api/check/health` is free and returns the scope, the rulebook and the price.

The body is exactly one key, `wallet`, at most 64 characters, in at most 1 KB. The address may be lowercase, uppercase, or mixed case with a correct checksum; a wrong checksum is refused as a likely typo.

Answers are cached by canonical address, chain and rulebook version, so every spelling of a wallet shares one model run. An accepted answer is kept 24 hours. A hold from a failed or refused screening is kept 5 minutes.

While one request screens a wallet, another for it gets `202` with `{"pending": true}`. Ask again later; a screening can take up to 120 seconds. If the server copy that was screening stops part way, that wallet keeps answering `202` for up to 330 seconds, until its place frees itself.

| Ceiling | Value |
| --- | --- |
| Requests per caller in 60 seconds, cached or not | 20 |
| New checks per caller per hour | 5 |
| New checks running per caller | 1 |
| New checks running on the service | 2 |
| New checks started on the service per UTC day | 300 |

The first three refuse with 429 and the last two with 503, both with `{"busy": true}`. A cached answer counts only toward the first.

## The paid route

x402 puts payment inside the HTTP request: the server answers 402 with terms, the client signs a USDC payment and asks again. `POST /api/x402/screen` costs $0.05, exactly `50000` USDC base units. A server runs on one network, set with no default: Base (`eip155:8453`, USDC `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`) or Base Sepolia, the test network (`eip155:84532`, test USDC `0x036CbD53842c5426634e7929541eC2318f3dCF7e`). It has been proven only on Base Sepolia with test USDC.

That proof ran through the site's own route, on a local build of the site. Realised, with test USDC that has no value: one screening was bought for 5 cents and settled in [this transaction](https://sepolia.basescan.org/tx/0x84e902d8bdb21c6e2e639611997d7b9d046fa1e8379741096db960c4797f63a1). Ten copies of the same payment header were then sent, and none bought a result.

Send the free check's body, and the payment in `PAYMENT-SIGNATURE`. Terms come back in `PAYMENT-REQUIRED`. A payment may stay valid at most 300 seconds plus 30 seconds of clock allowance.

Errors, in the order the route checks:

| Status | Body | When |
| --- | --- | --- |
| 400 | `{"error": "the client address could not be read"}` | caller's IP unknown |
| 429 or 503 | `{"busy": true}` | caller past a limit, or the limit store unreachable |
| 413 or 400 | an `error` text | over 1 KB, not JSON, not exactly `wallet`, or a bad address |
| 503 | `{"busy": true}` | service at a ceiling, or its stores unreachable or full |
| 402 | an `error` text | no payment header, or one that does not match the terms |
| 402 | `{}` | refused at settlement, with a reason such as `payment_expired` |
| 503 | `{"retry": true}` | claim not recorded or outcome unknown; resend the same header, it never pays twice |
| 500 | `{"error": "internal error"}` | internal fault |

| Limit | Value |
| --- | --- |
| Paid requests in flight per caller | 1 |
| Requests per caller in 60 seconds, paid or not | 20 |
| Paid attempts per caller per hour that end unsettled | 5 |
| Paid requests in flight on the service | 4 |
| Screenings started on the service per UTC day | 600 (596 with a shared database) |
| SERV calls per screening | 12 |
| Seconds per screening, then a hold | 120 |

A caller is its IP address, read from the host's trusted header. With `DATABASE_URL` set, used payments, limits and the cache live in Postgres, shared by every server copy; without it they reset on restart. `GET /api/x402/health` is free and returns the network, receiving address, price and scope.

## What comes back

A paid success is `200` with a `PAYMENT-RESPONSE` header. The free check returns the same fields.

- `wallet`, `checkedAt`: checksummed address; ISO 8601 time.
- `scope`, `rulebook`: always `one wallet on Ethereum, no claim list` and `v2`.
- `decision.action`: `full`, `partial`, `hold` or `exclude`.
- `decision.shareBps`: 0 to 10000; full 10000, partial 5000 by default, hold and exclude 0.
- `decision.rule`: `A1` to `A9`, `B1` or `B2`.
- `decision.reason`: plain text, 1 to 400 characters; show it as text only.
- `decision.citedTxs`: up to 256 transaction hashes.
- `servRequestId`: SERV's run id, or null.
- `notChecked`: `group`, `sharedDepositAddress`, `fundingBurst`, `claimPaidToOtherAddress`. A lone wallet has no list to measure them against, so they are marked not checked, not counted as doubt, and a `full` or `partial` answer says only that its own history raised no hold.
- Paid only: `payment` with `network`, `payer`, `transaction`. Free only: `cached`.

## Real captured examples

`packages/api/examples/` holds three answers captured from a local build of the site: `payment-required.json`, `paid-screen-response.json` and `free-check-response.json`. The parts below are copied from them.

`payment-required.json` is what the paid route sent to a request with no payment: the terms from `PAYMENT-REQUIRED`, decoded. Its one accepted payment, with the indentation reduced:

```json
{
  "scheme": "exact",
  "network": "eip155:84532",
  "amount": "50000",
  "asset": "0x036CbD53842c5426634e7929541eC2318f3dCF7e",
  "payTo": "0x93d50219322Bf8B7145FE3780a087ec1EC564C2e",
  "maxTimeoutSeconds": 300,
  "extra": {
    "name": "USDC",
    "version": "2",
    "paymentFlow": "upfront"
  }
}
```

That asks for `50000` base units, 5 cents, of Base Sepolia test USDC, paid to the `payTo` address. The value `upfront` means the payment settles before the screening runs.

`paid-screen-response.json` is the whole `200` body of the paid call that settled in the transaction linked above:

```json
{
  "wallet": "0x041f77015fe51c51aE49a7f2F3Ff86C641fa190a",
  "checkedAt": "2026-11-11T07:49:55.310Z",
  "scope": "one wallet on Ethereum, no claim list",
  "rulebook": "v2",
  "decision": {
    "action": "partial",
    "shareBps": 5000,
    "rule": "A8",
    "reason": "A8: The wallet is 261 days old with 3 pre-snapshot activities. No linked group, shared funding, shared collector, wallet-made links, or shared exchange claimants are recorded; the funder is unknown and its claimant count is unreadable.",
    "citedTxs": []
  },
  "servRequestId": "0fc3aea3-9a57-41e1-9d4b-c474c3df9899",
  "notChecked": [
    "group",
    "sharedDepositAddress",
    "fundingBurst",
    "claimPaidToOtherAddress"
  ],
  "payment": {
    "network": "eip155:84532",
    "payer": "0x86D40838B9805FF63343B8F060EF3fC336f59E78",
    "transaction": "0x84e902d8bdb21c6e2e639611997d7b9d046fa1e8379741096db960c4797f63a1"
  }
}
```

This wallet is also in the ROBO replay, where it is held on rule A4 as one of 19 linked wallets. Screened alone, it has no list around it, so the paid route cannot see that group. It answered partial on rule A8 and listed `group` under `notChecked`. Read a `full` or `partial` answer as "its own history raised no hold", not as "it belongs to no group".

`free-check-response.json` is a free check of a different wallet. It has the same fields, with no `payment` and with `"cached": false`, and it came back `full` on rule `A9`.

## The two-sided rule

Nothing is served without a settled payment, and a settled payment always gets its result. The route settles first, then screens, and a second copy of one signed payment fails at settlement. A failed screening still returns a hold on rule `A1` that names the cause. Open cases are on [limits](/docs/limits).
